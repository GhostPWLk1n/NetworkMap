# NetworkMap — первая сборка

Минимальный работающий каркас: Electron + SQLite (better-sqlite3), без канвы плана —
она добавляется следующим шагом поверх этого фундамента.

## Что уже работает
- База данных SQLite создаётся автоматически при первом запуске
  (`schema.sql` применяется, если таблиц ещё нет). Если БД уже существует
  (у вас с прошлой сборки), при старте автоматически прогоняется миграция
  схемы — данные не теряются, просто добавляются новые колонки/таблицы.
- Версия приложения показывается в шапке (`vX.Y.Z`, из `package.json`) —
  журнал изменений ведётся в [CHANGELOG.md](./CHANGELOG.md), начиная с v1.0.0.
- **Шесть листов**: «Планы», «Пользователи», «Устройства», «Склад», «ПО», «Сеть».
- **Кабель — полигональная линия со своими точками редактирования**, можно
  провести и без устройств на концах. Клик — точка маршрута, правый клик —
  завершение; выделенный кабель показывает перетаскиваемые точки (перенести
  трассу) с удалением точки правым кликом. Правый клик по самой линии — ещё
  «➕ Добавить точку» (на ближайшем сегменте к месту клика) и
  «➡️ Продолжить из последней точки» (дорисовать тот же кабель дальше, не
  создавая новый). Кабель получает автоматический номер и необязательное
  пользовательское имя — «Кабель №42 (Магистраль А)», редактируется в
  инспекторе. Разные кабели, идущие рядом, автоматически получают разный
  цвет из палитры и визуально расходятся небольшим параллельным сдвигом,
  если их путь совпадает.
- **Подключение устройства к кабелю напрямую** — «🔌 Подключить» в
  инспекторе (список всех кабелей этажа, ближайший сверху), либо
  автоматически при размещении, если устройство попало в ту же клетку, что
  и линия. Роутер/свитч — многопортовые: можно подключиться сразу к
  нескольким кабелям, не теряя предыдущие подключения. Любое другое
  устройство — только к одному кабелю разом: подключение к новому
  автоматически снимает старое.
- **Вкладка «Сеть»** — иерархия от выбранного корня (роутера/свитча):
  устройства на одном кабеле — сетевой сегмент, братья друг другу в дереве
  («🔌 Кабель №… (имя)», кликабельно — переключает на план и подсвечивает
  его); для связей, которые кабелем не проведёшь (например, между
  этажами), — ручной аплинк в инспекторе роутера/свитча («куда подключён» —
  другой роутер/свитч/сервер, «🔗 по аплинку»). Если на сегменте несколько
  роутеров — роль каждого (Главный/Резервный/Сателлит) задаётся вручную и
  показывается бейджем в дереве. Клик по названию устройства в дереве
  открывает его карточку. Переключение на вкладку всегда перечитывает
  дерево заново (плюс кнопка «🔄 Обновить»). «🔄📶 Пинговать дерево»
  пингует все устройства разом — узлы ниже недоступного автоматически
  помечаются как возможные жертвы каскада, а не отдельная проблема, что
  сразу показывает, где на самом деле сбой.
- Списанные устройства и уволенные сотрудники скрыты по умолчанию — тумблер
  «показать списанные»/«показать уволенных» в расширенном поиске возвращает
  их в список (приглушённым серым цветом). Кнопки «🗑 Списать»/«🚪 Уволить»
  и «♻️ Восстановить в правах» на карточке — без открытия формы
  редактирования целиком. Такие записи не предлагаются в карманах на плане.
- **Пометки «🟠 Проблема» / «🟡 Внимание» / «🔴 Ошибка»** — у пользователей,
  устройств, складских позиций и ПО; ставятся и снимаются правым кликом по
  карточке. Отдельно — автоматическое обнаружение конфликта (устройство
  закреплено за уволенным сотрудником) без ручной простановки. Строки
  дополнительно подсвечиваются по статусу (ремонт/на складе у устройств,
  в заказе/выдано/списано у склада). Статусы устройств — на русском везде
  в интерфейсе (хранение в БД не менялось). То же самое видно и на канве
  плана: рамка иконки устройства окрашена по статусу, цветная точка внизу
  слева — пометка или авто-конфликт; обновляется сразу, без перезагрузки.
- **Ручное комментирование на плане** — отдельный инструмент, независимый от
  пометок выше. Правый клик по столу/устройству на канве → «⚠️ Пометить "на
  проверку"…» с произвольным текстом (например, когда не уверены в точности
  данных). Помеченный объект получает жёлтый треугольник с восклицательным
  знаком перед маркером online на иконке устройства; текст виден в
  инспекторе. Снимается/редактируется тем же правым кликом.
- **Слои плана** — 🟩 зоны (слой 0, базовый, под всем остальным),
  🧱 стены/мебель (слой 1), 🔌 кабель-менеджмент (слой 2), 🖥 оборудование
  (слой 3). У каждого слоя три состояния: видимый / заблокирован / скрыт.
  Клик по кнопке — быстрое переключение видимый↔скрыт; правый клик — меню с
  явным выбором всех трёх. Заблокированный слой виден, но его объекты нельзя
  двигать/удалять/рисовать новые; связанные кнопки тулбара и карманы сереют.
  Настройка глобальная, не сбрасывается при смене этажа. Z-порядок объектов
  на канве всегда соответствует номеру слоя, независимо от порядка создания
  (элемент нижнего слоя не может оказаться визуально выше элемента верхнего).
- **Пользователи/Устройства/Склад/ПО** — карточный список: клик по строке
  разворачивает карточку для редактирования (сохранение — кнопкой «Сохранить»,
  без перезагрузки страницы). Удаление убрано с глаз — доступно через правый
  клик (контекстное меню: Редактировать / у устройств и ПО ещё «Найти на
  плане» / Удалить).
- **Склад**: комплектующие и лицензии ПО — снятые с устройств («Снять» в
  инспекторе плана) **или добавленные напрямую** («+ Добавить на склад» на самом
  листе — не нужно сперва цеплять деталь к какому-то ПК). У каждой позиции —
  редактируемый **статус** (в заказе / в наличии / выдано / списано) и
  необязательная **стоимость**. Карточка позволяет выдать позицию на любое
  устройство (кнопка в карточке или перетаскиванием из кармана «Склад» на
  плане); списание и безвозвратное удаление — через контекстное меню.
- **ПО**: единый реестр — установленное на устройствах (`device_software`) и
  лежащее на складе (`warehouse_items`, категория ПО) показаны вместе, с меткой
  «установлено на «X»» / «на складе» / «в заказе» / «списано». Добавить ПО можно
  прямо с этого листа («+ Добавить ПО» — попадёт на склад со статусом по
  выбору) или из инспектора конкретного устройства. «Снять и на склад»
  переносит установку в Склад, сохраняя ключ и стоимость.
- **Стоимость** (необязательная) есть у комплектующих и ПО везде, где они
  заводятся — в инспекторе устройства, на листе Склад, на листе ПО — и
  сохраняется при любом перемещении (снятие на склад → повторная выдача на
  другое устройство).
- **Кнопка «🔧 Сервис»** на карточке устройства — быстрая отправка в статус
  «на ремонте» с комментарием; любая смена статуса (в том числе через обычное
  редактирование карточки) пишется в историю статусов устройства.
- **Единый поиск в инструментах плана** — одно поле фильтрует сразу три кармана
  (пользователи, устройства, склад), вместо отдельного окошка на каждый список.
  Поиск двунаправленный: имя пользователя находит и закреплённые за ним
  устройства, а hostname/IP/тип устройства находит и его владельца.
- Строка поиска на всех карточных листах — с тумблерами **Аа** (регистр) и **\*** (wildcard:
  `*`/`?`), плюс кнопка **⚙** открывает панель расширенных фильтров (пока —
  заготовка: у пользователей фильтр по отделу, у устройств — по типу и статусу,
  у склада — по категории и «только в наличии», у ПО — по типу; остальное
  дополняется по мере надобности). Шапка (поиск + «+ Добавить») закреплена —
  список карточек ниже скроллится отдельно, не утаскивая её за собой.
- Сохранение карточки устройства (hostname, тип, IP) или пользователя (имя)
  сразу видно на плане — иконка на текущем открытом этаже перерисовывается
  без переключения листов.
- Карточка устройства — кнопка **📍 Найти на плане**: переключает на лист
  «Планы», открывает нужный этаж (если устройство размещено не на текущем),
  выделяет иконку и подсвечивает её пульсирующим красным кольцом (3 раза,
  чтобы не потерялась из виду на маленькой иконке). Развёрнутая карточка
  показывает те же Комплектующие/Периферию/ПО/Историю статусов/Историю
  владельцев, что и инспектор на плане — без старых текстовых полей
  ОС/CPU/RAM/Диски от первого импорта, которые дублировали эти данные и не
  обновлялись при выдаче со склада.
- Карточка пользователя — симметрично: показывает, какими устройствами он
  владеет сейчас и владел раньше (с периодом), с теми же кнопками перехода.
- **Мультиэтажность плана** — переключатель «Этаж 1 / Этаж 2 / …» + «+ Этаж»
  над канвой. У каждого этажа своя сетка, свои объекты, кабели и конструктив —
  полностью независимые планы. Правый клик по вкладке этажа — переименовать
  или удалить (вместе со всеми объектами; нельзя удалить последний план).
- Полнотекстовый поиск по устройствам (FTS5) — по hostname/инв.номеру/заметкам,
  плюс отдельный поиск по IP. Поиск на вкладке «Устройства» также ищет по
  установленному оборудованию — комплектующим, периферии и ПО (включая
  лицензионный ключ), а не только по полям самой карточки устройства.
  Там же — автодополнение по реальным значениям из данных (не история
  запросов) и счётчик «N из M» рядом со строкой поиска.
- Пинг устройства по IP (кнопка в карточке или в инспекторе плана), результат
  пишется в `ping_log`. Индикатор online/offline/timeout — цветная точка в
  карточке и цветной бейдж на иконке плана. Массовый пинг — «🔄📶» рядом с
  масштабом (весь этаж), в инспекторе зоны (только она) и в инспекторе
  роутера/свитча («Пинг подключённых устройств» — обход по уже нарисованным
  кабелям от этого узла, не трогая изолированные от него устройства).
- Фильтр «без пользователя» на вкладке «Устройства» — рядом с «показать
  списанные», учитывается в счётчике результатов.
- Канва плана: сетка 900 клеткой 96×54 («4K», 3840×2160 при масштабе 100% —
  новые планы сразу такого размера, старые подрастают до него автоматически
  при первом запуске после обновления, без потери позиций объектов),
  drag&drop столов (клик-режим) и устройств (перетаскивание из кармана
  «Устройства» — тот же паттерн, что у пользователей и склада, единым
  стилем) с примагничиванием к сетке, зум колёсиком мыши или кнопками
  (30–300%), исходный масштаб при открытии плана — 100%. Иконки устройств
  различаются по типу (ПК/ноутбук/сервер/VM/роутер/свитч/принтер) — та же
  иконка, что и всегда; под ней мелким шрифтом hostname и владелец, всё в
  пределах одной клетки, без отдельной второй карточки.
- **Переключатель «✏️ Рисование» / «🔒 Просмотр»** рядом с зумом/сбросом —
  в просмотре весь тулбар блокируется, объекты и подписи зон нельзя
  перетаскивать или удалять (ни клавишей Delete, ни кнопкой, ни через
  контекстное меню), удобно, когда план открыт просто для справки.
- **Из инспектора плана — прямо на карточку**: у выбранного устройства
  кнопки «📇 Открыть карточку устройства» и «👤 Открыть карточку
  пользователя» переключают лист и разворачивают нужную запись; то же — у
  каждого объекта в списке «Объекты в зоне».
- Инструменты рисования: стена (клик-клик; можно закончить на другой стене
  или двери — клик по существующему конструктиву завершает текущую стену
  прямо в этой точке, не перехватывается выделением), сетевой кабель (клик
  по устройству — начало, промежуточные клики — точки маршрута, клик по
  второму устройству — конец). Дверь встраивается только в существующую
  стену — клик рядом с ней находит стену и врезает дверь длиной 1 клетка;
  в инспекторе двери — «↔ Развернуть» (в какую сторону открывается) и
  «⇋ Отразить» (с какого края петля), 4 независимых состояния. Лестница —
  прямоугольная область произвольного размера (растягивается на столько
  клеток, на сколько провели), без скруглённых углов, ступени и стрелка
  направления идут от края до края области. Во всех режимах клика (стол,
  стена, лестница) под курсором видно превью объекта до того, как он будет
  установлен.
- **Зоны** — перетащите «🟩 Зона» из инструментов внутрь замкнутого стенами
  контура: заливка автоматически распространится по контуру, затем можно
  ввести название. Название — отдельная подпись, свободно перемещается по
  плану и поворачивается на произвольный угол; можно скрыть в инспекторе
  зоны, не удаляя саму зону. Инспектор устройства показывает его зону (если
  есть), инспектор зоны — список объектов внутри неё; поиск на плане ищет
  и устройства по названию их зоны, и сами зоны по названию.
- Панорамирование — зажатая средняя кнопка мыши (колесо) тянет план, как в
  большинстве графических редакторов; отдельно от зума колёсиком.
- Инструмент «Удалить» на плане — отдельный режим тулбара; либо выделить
  объект и нажать Delete. Esc отменяет текущее рисование.
- **Подключение к базе данных** — кнопка «🗄 БД» в шапке. По умолчанию
  используется локальный файл в `userData`, но можно подключиться к
  `.db`-файлу по любому пути, в том числе сетевому (например, шаре, которую
  раздаёт контейнер в Docker), или создать новую пустую БД в другом месте.
  Переключение вступает в силу после автоматического перезапуска
  приложения. Если сохранённый сетевой путь на момент запуска недоступен,
  приложение не падает — открывает локальную копию и явно предупреждает
  (жёлтый индикатор на кнопке). Важно: SQLite — файловая БД, а не сетевой
  сервер, поэтому одновременная запись с нескольких компьютеров через
  сетевую шару ограниченно надёжна — это свойство самого SQLite, не
  ограничение приложения; для полноценной многопользовательской работы в
  будущем понадобился бы отдельный сервер БД (Postgres/MySQL).
- **Владение устройством** — перетащите пользователя из кармана «Пользователи»
  (слева, лист «Планы») на иконку ПК на плане, чтобы закрепить его. Открепление —
  кнопкой в инспекторе. Каждое назначение/снятие пишется в историю с датой
  (`device_user_history`), видно в инспекторе выбранного устройства.
- **Комплектующие, периферия и ПО** устройства — с историей установки/снятия
  (`device_components`, `device_peripherals`, `device_software`), всё в инспекторе
  выбранного устройства на плане. «Снять» у комплектующих и ПО отправляет их
  на склад (не просто убирает пометку) — периферия склад пока не затрагивает,
  снимается как раньше.
- **Импорт из Excel** (лист «Пользователи» → «📥 Импорт из Excel») — читает
  список ПК с комплектующими (формат СПК), создаёт устройства, пользователей,
  историю владельцев (текущий + предыдущие — для последних даты неизвестны,
  так помечено в примечании), комплектующие и периферию. Строки с явным сдвигом
  колонок не «чинятся» автоматически — попадают в отчёт с предупреждением
  для ручной проверки. Повторный импорт того же файла не дублирует устройства
  (сверка по инвентарному номеру), но докидывает новых предыдущих владельцев в историю.

## Запуск

```bash
npm install
npm start
```

`npm install` теперь сам пересобирает `better-sqlite3` под ABI Electron
(скрипт `postinstall` → `electron-rebuild`) — это нужно, т.к. Electron использует
свой встроенный Node.js, отличный от системного, и нативные модули должны быть
собраны именно под него, а не под `node -v` с вашей машины.

Если после `npm install` при `npm start` всё равно видите ошибку вида
`NODE_MODULE_VERSION ... This version of Node.js requires NODE_MODULE_VERSION ...`,
пересоберите вручную:

```bash
npx electron-rebuild -f -w better-sqlite3
```

При первом запуске файл БД создаётся в стандартной папке userData приложения
(на Windows — `%APPDATA%/network-map-app/data.db`, на macOS —
`~/Library/Application Support/network-map-app/data.db`, на Linux —
`~/.config/network-map-app/data.db`).

## Сборка инсталлятора

```bash
npm run build               # под текущую ОС
npm run build:win           # под Windows — сразу и установщик (nsis), и portable .exe
npm run build:win:portable  # под Windows — только portable, без установки в систему
npm run build:mac           # под macOS (dmg)
npm run build:linux         # под Linux (AppImage)
```

Portable-версия — один `.exe`, ничего не пишет в реестр/Program Files, можно
носить на флешке или запускать с сетевого диска на сервере. Кросс-сборка
Windows-таргета с Linux/macOS требует `wine` (на самой Windows или в
Windows-раннере CI — не нужен, соберётся нативно).

Готовые файлы появятся в `dist/`.

## База данных на сервере (Docker)

Приложение хранит все данные в одном файле SQLite (`data.db`). У SQLite нет
сетевого протокола — она не «сервер, к которому подключаются», а обычный
файл, который открывает конкретный процесс на конкретной машине. Поэтому
«база в Docker» на практике означает: контейнер отдаёт папку с файлом по
сети, а приложение просто открывает файл по этому сетевому пути — как если
бы он лежал на общем сетевом диске.

Пример — Samba-шара в Docker (Windows-путь `\\сервер\netmapdb\data.db`):

```bash
docker run -d --name netmap-db-share \
  -p 445:445 \
  -v /srv/netmap-db:/share \
  -e USER=netmap -e PASS=подставьте_пароль \
  dperson/samba -s "share;/share;yes;no;no;netmap"
```

Дальше в приложении: «🗄 БД» → «📂 Подключиться к существующему файлу…» (если
файл уже лежит в `/srv/netmap-db/data.db`) или «💾 Создать новую БД в другом
месте…» (если начинаете с нуля) → указываете путь на смонтированной шаре.
После подтверждения приложение перезапустится и будет открывать именно этот
файл при каждом следующем запуске.

**Важно понимать ограничение**, а не рассчитывать на него как на полноценный
сервер БД:
- Подходит, когда с базой в один момент времени активно работает
  практически один человек (остальные — в основном смотрят план), это
  обычная история для файловой БД на сетевом диске.
- Одновременная **запись** с нескольких машин через сетевую шару (SMB/NFS)
  ненадёжна для SQLite — это задокументированное ограничение самого SQLite
  при блокировках файла по сети, а не недоработка этого приложения.
- Если нужна полноценная многопользовательская работа с гарантированной
  корректностью при параллельной записи — правильный путь в перспективе:
  перейти на настоящий сервер БД (PostgreSQL/MySQL в том же Docker), но
  это отдельная, более крупная переработка (сейчас все SQL-запросы
  написаны под диалект SQLite через `better-sqlite3`).

   от устройства, к которому они сейчас привязаны.
7. Установленное на устройстве ПО (в отличие от складских карточек, которые
   теперь полностью редактируемы) по-прежнему меняется только через
   снятие+повторную установку — при необходимости можно добавить полноценный
   `software:update`, как уже сделано для warehouse-карточек.
8. Заливка зоны учитывает только горизонтальные/вертикальные стены — если
   стену когда-нибудь научат рисоваться по диагонали, флуд-филл её пока не
   заметит и «протечёт» через такую границу. Также заливка не требует
   полного замыкания периметра стенами — если в контуре есть разрыв, область
   расползётся до края сетки или до ближайшей настоящей преграды (это
   осознанное упрощение, а не баг: так проще пользоваться, когда не все
   стены участка прорисованы).
