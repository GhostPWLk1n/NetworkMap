# Релизноут: v1.16.0 → v1.27.0

Сводка всего, что изменилось с последнего известного релиза (v1.16.0) по
текущий (v1.27.0). Подробности по каждой версии — в [CHANGELOG.md](./CHANGELOG.md).

---

## Главное за этот цикл

1. **Пять строгих слоёв** плана (v1.17.0 → v1.22.0) — зоны → стены →
   столы → кабели → оборудование, каждый со своим независимым
   видимый/заблокирован/скрыт; z-порядок гарантированно соответствует
   номеру слоя независимо от порядка создания объектов.
2. **Вкладка «Сеть»** (v1.18.0) — иерархия сети от роутера/свитча, дважды
   переработанная модель подключения устройств (сначала сокеты, затем —
   прямое подключение к ближайшему кабелю), диагностика каскадных сбоев
   по пингу (v1.20.0).
3. **Кабель как самостоятельный путь** (v1.19.0–v1.21.0) — полигональная
   линия с точками редактирования, можно провести без единого устройства,
   многопортовые роутеры/свитчи, контекстное меню «Добавить точку» /
   «Продолжить из последней точки».
4. **Вкладка «Журнал»** (v1.23.0) — лог значимых действий по всему
   приложению, лимит 10 000 записей, фильтр по датам и типу сущности.
5. **Импорт сведений о ПК из JSON** (v1.24.0–v1.25.0) — PowerShell-скрипт
   собирает железо/ОС/сеть/ПО/комплектующие на компьютере пользователя,
   приложение импортирует с интерактивным разрешением расхождений.
6. **Метаданные и иконка сборки** (v1.25.1–v1.26.0) — author/license/
   homepage, иконка приложения, имя portable-артефакта.
7. **UX-улучшения плана** (v1.26.0–v1.27.0) — превью точки старта стены
   и места посадки при перетаскивании, ручной способ решить визуальное
   перекрытие объектов.
8. **Два системных бага исправлены** (v1.22.0): нативные `confirm()`/
   `alert()` намертво блокировали интерфейс Electron — заменены на
   собственные модалки везде, где встречались (16 мест); слой «столы»
   был случайно объединён со слоем «стены».
9. **Portable-сборка для Windows** (v1.21.0) — `.exe` без установки.

## Версия за версией

### v1.17.0
- Три состояния слоя (видимый/заблокирован/скрыт) вместо двух.
- Гарантированный z-порядок объектов на канве независимо от порядка создания.

### v1.18.0
- Вкладка «Сеть»: иерархия от роутера/свитча по нарисованным кабелям +
  ручной аплинк для связей, которые кабелем не проведёшь (например, между
  этажами).
- Полный пересчёт z-порядка при загрузке этажа — страховка сверх точечной
  вставки новых объектов.

### v1.19.0 / v1.19.1
- Кабель — полигональная линия со своими точками редактирования, можно
  провести без устройств на концах.
- Первая версия подключения устройств к сети — через сокеты на кабеле.
- Найден и исправлен баг: устройства в *соседних* клетках не находили
  друг друга в дереве сети — расширенный порог автоподключения плюс явный
  выбор сокета в инспекторе устройства.

### v1.20.0
- Настоящая причина более раннего отчёта «устройство не видно в дереве»:
  подключение работало исправно, но само дерево не перечитывалось при
  возврате на вкладку. Переключение на вкладку теперь всегда обновляет
  дерево, плюс кнопка «Обновить».
- Диагностика каскадных сбоев: кнопка «Пинговать дерево» — узлы ниже
  недоступного узла помечаются как возможные жертвы каскада, а не
  отдельная проблема.

### v1.21.0
- Вторая, более крупная переработка модели сети: сокеты убраны как
  отдельная сущность, устройство подключается напрямую к ближайшему
  кабелю.
- Кабель получил номер и необязательное имя («Кабель №42 (Магистраль А)»).
- Исправлен главный баг дерева: несколько устройств на одном кабеле
  показывались цепочкой вместо братьев под общим узлом — переписано на
  двухфазный алгоритм.
- Контекстное меню на линии кабеля — «Добавить точку», «Продолжить из
  последней точки».
- Клик по устройству в дереве — открывает карточку; клик по кабелю —
  переключает на план и подсвечивает его.
- Portable-сборка для Windows — `npm run build:win:portable`.

### v1.22.0
- Баг «блокировка интерфейса после увольнения пользователя»: причина —
  нативный `window.confirm()`/`window.alert()`, который в Electron
  периодически намертво блокирует интерфейс. Заменены **все** 16 мест
  (13 `confirm()` + 3 `alert()`) по всему приложению на собственные
  модальные окна.
- Баг со слоями: столы делили один логический слой со стенами — их
  взаимный z-порядок был непредсказуем. Разнесено на 5 строгих слоёв;
  заодно исправлен баг, из-за которого создание нового стола вообще
  проверяло блокировку не того слоя.

### v1.23.0
- Вкладка «Журнал»: лог создания/удаления/смены статуса по всем разделам
  приложения, лимит 10 000 записей с автообрезкой старых, фильтр по датам
  и типу сущности.

### v1.24.0 / v1.24.1 / v1.24.2
- **Импорт сведений о ПК из JSON** — `scripts/collect-pc-info.ps1` +
  `collect-pc-info.bat` собирают ОС/CPU/RAM/диски/сеть/ПО в один файл
  (ПО — из реестра, не через `Win32_Product`, который тормозит и
  триггерит переустановку). Импорт в приложении — одиночный (в карточку
  конкретного устройства) или пакетный (вся папка разом), с интерактивным
  разрешением расхождений по каждому полю при совпадении hostname.
  Повторный импорт не плодит дубликаты ПО.
- Исправлено: `.ps1` не запускался из-за отсутствия UTF-8 BOM (Windows
  PowerShell 5.1 без BOM читает скрипт в системной ANSI-кодировке —
  кириллица рвёт строковые литералы). Заодно найден и исправлен связанный
  баг: сам собранный JSON-файл тоже получается с BOM (та же PowerShell
  5.1 так пишет по умолчанию) — `JSON.parse()` на нём падает; теперь BOM
  снимается перед разбором.
- Исправлено: `%~dp0` в батнике всегда заканчивается на `\` — в кавычках
  перед закрывающей кавычкой это ломает путь («Путь содержит недопустимые
  знаки»). Убран завершающий слеш перед передачей в PowerShell.

### v1.25.0 / v1.25.1
- Импорт из JSON заполнял только текстовые поля карточки устройства, но
  не «Комплектующие» — диски/память/видеокарта не появлялись отдельными
  позициями инвентаря. Возвращены `MemoryModules`/`Video` в скрипт сбора,
  импорт теперь создаёт отдельную запись комплектующего на каждую
  позицию. Дедупликация переделана с булевой на количественную — иначе
  парный комплект одинаковой памяти схлопывался бы в одну запись уже при
  первом импорте.
- Метаданные `package.json`: `author`, `license` (MIT), `homepage` —
  подхватываются `electron-builder` в собранный установщик.

### v1.26.0
- Иконка приложения (`build/icon.ico`) и имя portable-артефакта.
- Превью точки старта стены/лестницы до первого клика — как у стола/
  двери, под курсором сразу видно, куда снапнется начало линии.
- Превью места посадки при перетаскивании на план (устройство,
  пользователь, склад, зона) — контур клетки под курсором на `dragover`.

### v1.27.0
- «⬆️ Поднять поверх всего» в контекстном меню объекта на плане — ручной
  способ решить визуальное перекрытие, в обход обычного порядка слоёв.
- Защитная мера: `dragend` точечных объектов тоже пересчитывает z-порядок
  после перетаскивания.
- Открытая проблема (см. ниже) — перекрытие объектов при перетаскивании
  существующего стола/устройства, первопричина не найдена несмотря на
  восемь проверенных сценариев, включая настоящий Konva `startDrag()`/
  `stopDrag()`. Кнопка ручного подъёма и защитная мера в `dragend` —
  подстраховка, а не подтверждённое устранение причины.

## Как обновиться

Распакуйте архив поверх текущей папки проекта, затем:

```bash
npm install
npm start
```

Миграции БД (с v10 по v14) применятся автоматически при первом запуске.
Если вы уже пользовались вкладкой «Сеть» на основе сокетов (версии
v1.19.x–v1.20.x) — учтите: при переходе на v1.21.0+ сокетные подключения
**не переносятся** (это было сознательное решение — сеть на тот момент ещё
не была спроектирована всерьёз). Устройства и кабели сохраняются,
теряется только сама привязка «кто к чему подключён» — переподключите
заново через инспектор.

### Сборка установщика

```bash
npm run build:win            # nsis + portable
npm run build:win:portable   # только portable
```

Перед сборкой под Windows положите иконку в `build/icon.ico` (в архиве
уже есть) — иначе `electron-builder` упадёт с «icon not found». Подробнее
про типичные проблемы `npm install` на Windows (устаревшая/canary-версия
Node, `Request timed out` при скачивании бинарников, отсутствие Python
или Visual Studio Build Tools) — в README, раздел «Возможные проблемы при
npm install на Windows».

## Открытые проблемы

- **Перекрытие объектов при перетаскивании** — не воспроизведено при
  тестировании (см. v1.27.0 выше), но подтверждено скриншотом. Если
  увидите снова: кнопка «⬆️ Поднять поверх всего» в контекстном меню
  должна чинить конкретный случай сразу; для поиска первопричины нужны
  точные шаги (что именно перетаскивали и куда) или видео/скринкаст
  самого момента.

## Известные ограничения (не изменились с прошлых версий)

- Диагональные стены не блокируют заливку зоны.
- Форма зоны фиксируется при создании — для изменения удалить и
  создать заново.
- «Найти на плане» берёт первый найденный этаж, если устройство/кабель
  размещено сразу на нескольких.
- Нет живого автообновления пинга — только вручную по кнопке.
