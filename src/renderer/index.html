      Подключение к базе данных
      —

      SQLite — файловая база, не сетевой сервер: «подключение» здесь означает просто открыть файл data.db по другому пути — например, сетевой шаре (Samba/NFS), которую отдаёт контейнер в Docker. Для одновременной записи с нескольких компьютеров это ограниченно надёжно — таково свойство самого SQLite, а не этого приложения.

      Совместный доступ (несколько компьютеров)

      Один компьютер («хост») держит файл БД у себя локально и раздаёт доступ остальным по сети — так файл никогда не открывают несколько процессов одновременно, и сама причина зависаний/конфликтов устраняется, а не смягчается. Компьютеры-«клиенты» подключаются к хосту по адресу — видят все данные, но по умолчанию не могут редактировать (только просмотр). Хост может разрешить клиентам вносить изменения отдельным переключателем ниже — по модели «взялся — ходи»: кто первый открыл объект для редактирования, тот и держит право на него, пока не закроет или не станет неактивен; занятые объекты видно на плане цветным контуром, а хост в любой момент может экстренно отключить конкретного клиента. «Папка для маячка» — необязательно: если раньше все указывали общий сетевой путь напрямую к файлу БД, укажите ту же папку здесь — хост опубликует туда свой адрес отдельным файлом (у каждого хоста — свой, никто не переписывает чужой, поэтому упавший хост никогда не помешает следующему, даже если его файл нельзя удалить из-за прав доступа на сетевой шаре). Тот, кто по привычке попробует «Подключиться к существующему файлу» и укажет эту папку, увидит подсказку с адресом активного хоста вместо невнятной ошибки.
